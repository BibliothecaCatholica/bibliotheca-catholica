# AGENTS.md: continuity guide for Bibliotheca Catholica

Read this before changing the site. It applies to every contributor and coding agent (Codex, ChatGPT, Grok Bot, and others). Owner: Micah Watson, micahwatson@bibliothecacatholica.com. Live site: https://bibliothecacatholica.com (GitHub Pages from `main`).

## Architecture

- **Static single-page app.** Vanilla HTML, CSS, and JavaScript: `index.html`, `app.js` (router and most views), `scripts/library.js` (reading room, work pages, LibriVox buttons), `scripts/guides.js` (edition guides and reading paths), `scripts/search.js`, `scripts/analytics.js` (GA4 event helper), `scripts/boot.js` (startup recovery), `scripts/timeline.js`, `scripts/saints.js`, `scripts/rights.js`, `scripts/rites.js`, `scripts/plans.js`, `styles.css` plus `styles/`. Routes are hashes (`#/author/<id>`, `#/work/<id>`, `#/read/<work>/<edition>`, `#/editions/<id>`, `#/reading/<id>` (lists and dated plans), `#/search/<term>`, `#/isidore/book/<n>`, `#/saints/...`, `#/rites/...`, `#/rights`, `#/takedown`, `#/licensing`, `#/policy`, `#/about`).
- **Reader (v11):** `scripts/reader.js` (loaded after `scripts/library.js`, before `app.js`) and `styles/reader.css` add highlights and notes, the sticky edition banner with progress, the contents sidebar (sticky at ≥1100px, a drawer below), keyboard shortcuts, the mobile bottom bar, Print / save as PDF, and Continue reading. `scripts/library.js` `read()` calls `BCReader.enhance(...)` after rendering a section; the home page and Discover & Read call `BCReader.continueRow()`. Pure logic lives in `BCReader.core` and is tested in `tests/reader.test.js`. See "Reader storage and features" below.
- **Data lives in files, not a server.** `data/catholic-hub.json` (authors, resources, eras, Isidore names; the source of truth) is split by `tools/hubio.py` into `data/data.js` (core, loaded on every page: eras, resources, slim authors, `isidoreCount`), `data/authors-detail.js` (extract, links, intro, books, media, full portrait credit; lazy, author page and timeline), and `data/isidore-authors.js` (lazy, search and the Isidore A-Z), `data/library.json` → `data/library.js` (selected works and editions), `data/guide.js` (edition guides and reading lists, built from `tools/editions_data.py` and `tools/reading_lists.py`), `data/reading-options.json/.js` (EPUB options), `data/isidore-matches.*`, `data/librivox.*`, `data/editorial-flags.*`, and `data/books.js` (the 6,633-record Isidore Index, lazy-loaded, about 1.2 MB). Each `.js` file is a generated copy of its `.json`; never edit only one of them.
- **Licensing:** see `LICENSING.md` (content rule 11). Code MIT, open data and catalog CC0, site writing CC BY 4.0, hosted texts no license, Wikipedia excerpts CC BY-SA 4.0.
- **No build step to serve.** The one generator that must be rerun is `python3 tools/build_static.py`. It pre-renders the static entry pages (765 on 2026-11-03, including `guides/epub-on-your-device/`; 764 on 2026-11-02: `author/`, `work/`, `editions/`, `reading/`, `saints/`, `rites/`, sections, `about/`, `policy/`, `search/`) from `index.html`, and it writes `sitemap.xml` (765 URLs including the home page on 2026-11-02; the build prints the current "N pages; M sitemap URLs" line, so check that rather than this note), `robots.txt`, and `404.html`. Since v17 it also rewrites the marked regions of `index.html` itself (see "SEO" below). **Rerun it whenever you change `index.html` (header, footer, script tags, meta), routes, authors, works, edition guides, reading lists, or editorial flags, and commit the output.** CI fails if the output is stale.

- When you bump the `?v=` cache-busting query on script tags in `index.html`, keep `data/data.js` as a script tag: `build_static.py` inserts `window.BC_BOOT` right before it.
- **Performance (Phase B item 5).** Every local script in `index.html` is `defer` (only `scripts/boot.js`, the watchdog, stays synchronous in the head; inline scripts may only set globals). Do not add an author field to the core without checking its size: anything only the author page reads goes in `hubio.DETAIL`. Routes that need the lazy files wait through `hubNeed()` in `app.js`; on a static page's first paint the prerender stays until they arrive (no layout shift). The two lazy files are cache-busted by the content tokens `detailV` and `isidoreV` in `data.js`, so they need no manual bump. Fonts are self-hosted (`styles/fonts.css`, `fonts/`, OFL texts in `fonts/`; no request to Google Fonts) and the two latin faces are preloaded. Static author and timeline pages also preload `data/authors-detail.js` (`build_static.py`).
- **Layout stability (Phase B item 6).** The header must not reflow when the web font arrives: `.brand-name` has a fixed width in `em` and the search input a fixed line height, so the header is 170 px at 1280, 121 px at 412, and 165 px at 390 with or without the fonts. The inline theme script in `index.html` adds `html.js`; with it, the static prerender in `#main` reserves `min-height:100vh` so the footer never shows in the first screen and then jumps when the app's page replaces it (`html.app-unavailable`, set by `scripts/boot.js`, drops the reservation). Check with a throttled CLS run at 412 px before changing the header, fonts, or prerender.

## Google Analytics (GA4)

- Measurement ID **`G-HFG445Y1LT`**. Every HTML content page must carry **exactly one** copy of the standard Google tag (gtag.js) snippet, placed immediately after `<head>`. The owner-supplied Search Console verification file `google3b007babfa8923a4.html` is a verification response, not a content page: retain its exact original bytes, add no analytics or HTML wrapper, and keep it published at the site root.
- The single source is `index.html`. `tools/build_static.py` copies it into every static page and into `404.html` (it fails if `index.html` has zero or two tags). Never paste the tag into generated pages by hand, never remove it, and never add a second tag, Google Tag Manager container, or another analytics script without the owner's approval.
- **Host gate (pages.dev mirror, 2026-11-09).** `BCAnalytics.allowedHost()` / `track()` are a no-op unless `location.hostname` is `bibliothecacatholica.com` or `www.bibliothecacatholica.com`. The inline `gtag('config', …)` in `index.html` is wrapped in the same check so the Cloudflare Pages preview (`*.pages.dev`) never configures the tag or sends events (it still loads the one gtag.js script; do not add a second tag). Keep exactly one GA4 measurement ID. Bump the `scripts/analytics.js?v=` cache token in `index.html` (and let `build_static.py` copy it) whenever the helper changes.
- **Page views (v14).** The config line is `gtag('config', 'G-HFG445Y1LT', {'send_page_view': false});`, so the tag sends no automatic page view. `app.js` `gaPageView()` sends exactly one `page_view` (`page_title`, `page_location`, `page_path`) for the first load (after the first `route()`, which also covers static entry pages through `window.BC_BOOT`) and one per later `hashchange`, debounced 400 ms and deduped by the raw URL. **v18:** `page_path` is the normalized route from `BCAnalytics.pagePath(location.hash, window.BC_BOOT)`, so one view logs one path whether it was served from `/` or a static page (`/work/x/#/author/y` and `/#/author/y` both give `/#/author/y`). Search and Isidore Index filter routes collapse to `/#/search` and `/#/isidore` (book pages keep `/#/isidore/book/N`), so no search term or filter ever reaches a page view; a segment that is not a plain slug ends the path. `page_location` is `https://bibliothecacatholica.com` plus that path (never `location.href`), and the title of those two collapsed routes is fixed too. **v18.1:** `track()` calls `gtag('set', {page_title, page_location})` with `BCAnalytics.context()` (the term-free `pageTitle()` and `pageLocation()` for the current route) before every event, so `search`, `outbound_click`, and GA's own events never fall back to a title or URL with free text, and `results()` sets `document.title` to the fixed `Search — Bibliotheca Catholica`. Never put a search term or Index filter in `document.title`. `404.html` carries the same config and no `app.js`, so it sends nothing; the `/#/...` page it redirects to counts the visit once. Do not remove `send_page_view: false`, and do not add a second page-view listener. The owner turns off GA4 enhanced measurement "page changes based on browser history events" in GA4 admin so hash changes are not counted twice. **Campaign tags (spec 2026-11-03):** the landing `page_view` only (the first one `gaPageView()` sends in a page load) appends to `page_location` the `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content` values from `location.search`, each trimmed and cut to 100 characters (`BCAnalytics.utmQuery()`). `utm_term`, `gclid`, `lookup`, `q`, and every other parameter are dropped; later page views and the `gtag('set')` context carry the bare route. **Tags before the `#` (QA 2026-11-03, owner-approved fix 2026-11-09):** GA4 reads campaign tags only from the query string of `page_location`, so `pageLocation()` always writes them before the fragment (`https://bibliothecacatholica.com/?utm_source=x#/work/y`, never `/#/work/y?utm_source=x`). Links that put the tags after the `#` still count: on the landing view `BCAnalytics.landingSearch(location.search, location.hash)` adds the hash's utm_ tags (a tag in `location.search` wins; the same four, each cut to 100 characters), the same `page_view` carries them (no new event), and `BCAnalytics.stripHashUtm()` then removes every utm_ pair from the hash with `history.replaceState` (other hash parameters stay; `gaLast` follows so the view is not sent twice). Tested in `tests/analytics.test.js`. **Built-in measurements:** the owner switched off GA4 enhanced measurement "Outbound clicks" and "Form interactions" on 2026-11-03, so GA's own `click` (with `link_url`), `form_start`, and `form_submit` events are no longer sent; the Privacy section says they are off. Keep them off: "Outbound clicks" would send full outside URLs, which for isidore.co and vatican.va search links include search terms.
- **Tagged links (for every bot, post, newsletter, and doc):** put the UTM query before the `#`: `https://bibliothecacatholica.com/?utm_source=x&utm_medium=social#/library`, or on a static page `https://bibliothecacatholica.com/work/orthodoxy/?utm_source=x&utm_medium=social`. Never `https://bibliothecacatholica.com/#/library?utm_source=x`. Use only `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content` (`utm_term` is dropped). Build them with `BCAnalytics.campaignUrl(route, tags)`, for example `node -e "console.log(require('./scripts/analytics.js').campaignUrl('#/library',{utm_source:'x',utm_medium:'social'}))"`.
- **Events (v14).** Every event goes through the helper `window.BCAnalytics.track(name, params)` in `scripts/analytics.js` (loaded once, after `data/affiliates.js` and before `scripts/library.js` and `app.js`). It checks `allowedHost()` first (production hostname only), then `typeof gtag==='function'`, wraps everything in `try/catch`, accepts only the event names below, drops empty values, and caps string params at 100 characters. `app.js` and `scripts/library.js` call it through a local `track()` wrapper; nothing else may call `gtag(` or touch `dataLayer`. GA4's own enhanced-measurement outbound `click`, `form_start`, and `form_submit` events are switched off (2026-11-03); if they are ever switched on again, they come from the tag itself, not our code, and the Privacy section must say so.

| Event | Params | Fired from |

## How to add things

- **Connected timeline:** `scripts/timeline.js` joins authors and the existing saints guide, with by/about reading links and rights-gated read-here buttons. Keep historical flags and the undated group. See `docs/TIMELINE.md` and `tests/timeline.test.js`.

- **A reading-room work or edition:** follow `docs/CATALOG.md`. Edit `data/library.json` (with rights evidence in `data/sources/`, plus `data/texts/` and SHA-256 if hosted), then run `npm run build`.
- **An author or resource:** load, edit, and save with `tools/hubio.py` (`load()` and `save()`) so `catholic-hub.json` and the three browser files (`data.js`, `authors-detail.js`, `isidore-authors.js`) stay in step (`python3 tools/hubio.py` rewrites them; `tests/test_catalog.py` checks). Author ids are kebab-case slugs used in URLs.
- **An edition guide or reading list:** edit `tools/editions_data.py` or `tools/reading_lists.py`, then run `npm run build`. Never add a flagged title.
- **A dated reading plan:** add its passage anchors to `tools/reading_plans.py` and its words to a `data/<planId>.json` text file like `data/advent-2026.json` (see "Dated reading plans" above), add its id to `IDS` in `scripts/plans.js` and its description to `PLAN_DESC` in `tools/build_static.py`, then run `npm run build` and `python3 tools/build_static.py`.
- **An editorial flag:** add the Isidore book id to `tools/build_editorial_flags.py` with a category (`antisemitic-content`, `polemical-historical`, `sedevacantist-position`, or `author-context`) and a factual note. Then run `python3 tools/build_editorial_flags.py`, `python3 tools/build_open_data.py`, and `python3 tools/build_static.py`.
- **A saint:** add the saint to `research/saints-pilot.json` (outside this repo) and rerun `python3 tools/import_saints_pilot.py --research <dir>`, or edit `data/saints.json` directly: every claim needs a `source_url`; tier 1 ids must equal a hub author id; tier 3 saints need a `historicity` flag. Then run `python3 tools/build_saints.py` (it validates, rebuilds the alias table, and fails on an ambiguous multi-word alias) and `python3 tools/build_static.py`. Search aliases: exact keys after NFKD, diacritic stripping, lowercasing, and dropping leading honorifics (Saint, St., Blessed, Pope); bare first names such as "John" are collisions shown as "Did you mean". Add a nickname (for example "Little Flower") to `HAND_ALIASES` in `tools/import_saints_pilot.py`.
- **A rights status:** add a hand-checked entry to `MANUAL` in `tools/build_rights.py`, rerun `python3 tools/build_rights.py --research <research dir>` (or without `--research` to keep the current classification), then `python3 tools/build_open_data.py` and `python3 tools/build_static.py`.
- **A Rites & Liturgy fact:** edit the research copy in `data/rites-src/` (or the review tables in `tools/build_rites.py`: `OVERRIDES`, `UNVERIFIED`, `DROP`, `PUBLIC_NOTES`, `RESOURCE_FIX`, and the cross-link lists), then `python3 tools/build_rites.py` and `python3 tools/build_static.py`. Every description must be 150 to 160 characters (`rites_pages.fit()` fails the build otherwise).
- **LibriVox audio:** run `python3 tools/fetch_librivox.py` (network) and review the matches.
- After any of these, run `python3 tools/build_static.py`.

## Hosting limits (checked 2026-11-09)

Production stays on GitHub Pages from `main` with the existing `CNAME` (do not change GitHub Pages settings or DNS here; Business owns DNS). A Cloudflare Pages mirror (`bibliotheca-catholica.pages.dev`) auto-deploys the same `main` root with no build step. The reading-room texts also live in the separate `bibliotheca-texts` repo. Tracked content is ~223 MiB / ~9k files (2026-11-09); Cloudflare Pages Free caps sites at **20,000 files** and 25 MiB per file — keep Pagefind `maxFragments` and avoid another Summa-scale HTML tree without budgeting file count.

- **GitHub Pages:** published site at most 1 GB; source repo recommended at most 1 GB; soft bandwidth limit 100 GB per month; deployments time out after 10 minutes; soft limit of 10 builds per hour (https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
- **Repository files:** warning above 50 MiB, blocked above 100 MiB (25 MiB through the browser); repos ideally under 1 GB, strongly recommended under 5 GB (https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
- **Releases:** up to 1,000 assets per release, each under 2 GiB; no limit on total release size or bandwidth (https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).
- So the ~32 GB of isidore.co files cannot go on Pages or in a repo; Releases could hold permitted files one by one, but nothing is hosted until each file is rights-checked and the owner approves.

## Study desk (2026-11-09)
