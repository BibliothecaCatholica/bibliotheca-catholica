## Architecture

- **Static single-page app.** Vanilla HTML, CSS, and JavaScript: `index.html`, `app.js` (router and most views), `scripts/library.js` (reading room, work pages, LibriVox buttons), `scripts/guides.js` (edition guides and reading paths), `scripts/search.js`, `scripts/analytics.js` (GA4 event helper), `scripts/boot.js` (startup recovery), `scripts/timeline.js`, `scripts/saints.js`, `scripts/rights.js`, `scripts/rites.js`, `scripts/plans.js`, `styles.css` plus `styles/`. Routes are hashes (`#/author/<id>`, `#/work/<id>`, `#/read/<work>/<edition>`, `#/editions/<id>`, `#/reading/<id>` (lists and dated plans), `#/search/<term>`, `#/isidore/book/<n>`, `#/saints/...`, `#/rites/...`, `#/rights`, `#/takedown`, `#/licensing`, `#/policy`, `#/about`).
- **Reader (v11):** `scripts/reader.js` (loaded after `scripts/library.js`, before `app.js`) and `styles/reader.css` add highlights and notes, the sticky edition banner with progress, the contents sidebar (sticky at ≥1100px, a drawer below), keyboard shortcuts, the mobile bottom bar, Print / save as PDF, and Continue reading. `scripts/library.js` `read()` calls `BCReader.enhance(...)` after rendering a section; the home page and Discover & Read call `BCReader.continueRow()`. Pure logic lives in `BCReader.core` and is tested in `tests/reader.test.js`. See "Reader storage and features" below.
- **Data lives in files, not a server.** `data/catholic-hub.json` (authors, resources, eras, Isidore names; the source of truth) is split by `tools/hubio.py` into `data/data.js` (core, loaded on every page: eras, resources, slim authors, `isidoreCount`), `data/authors-detail.js` (extract, links, intro, books, media, full portrait credit; lazy, author page and timeline), and `data/isidore-authors.js` (lazy, search and the Isidore A-Z), `data/library.json` → `data/library.js` (selected works and editions), `data/guide.js` (edition guides and reading lists, built from `tools/editions_data.py` and `tools/reading_lists.py`), `data/reading-options.json/.js` (EPUB options), `data/isidore-matches.*`, `data/librivox.*`, `data/editorial-flags.*`, and `data/books.js` (the 6,633-record Isidore Index, lazy-loaded, about 1.2 MB). Each `.js` file is a generated copy of its `.json`; never edit only one of them.
- **Licensing:** see `LICENSING.md` (content rule 11). Code MIT, open data and catalog CC0, site writing CC BY 4.0, hosted texts no license, Wikipedia excerpts CC BY-SA 4.0.
- **No build step to serve.** The one generator that must be rerun is `python3 tools/build_static.py`. It pre-renders the static entry pages (765 on 2026-11-03, including `guides/epub-on-your-device/`; 764 on 2026-11-02: `author/`, `work/`, `editions/`, `reading/`, `saints/`, `rites/`, sections, `about/`, `policy/`, `search/`) from `index.html`, and it writes `sitemap.xml` (765 URLs including the home page on 2026-11-02; the build prints the current "N pages; M sitemap URLs" line, so check that rather than this note), `robots.txt`, and `404.html`. Since v17 it also rewrites the marked regions of `index.html` itself (see "SEO" below). **Rerun it whenever you change `index.html` (header, footer, script tags, meta), routes, authors, works, edition guides, reading lists, or editorial flags, and commit the output.** CI fails if the output is stale.

- **Performance (Phase B item 5).** Every local script in `index.html` is `defer` (only `scripts/boot.js`, the watchdog, stays synchronous in the head; inline scripts may only set globals). Do not add an author field to the core without checking its size: anything only the author page reads goes in `hubio.DETAIL`. Routes that need the lazy files wait through `hubNeed()` in `app.js`; on a static page's first paint the prerender stays until they arrive (no layout shift). The two lazy files are cache-busted by the content tokens `detailV` and `isidoreV` in `data.js`, so they need no manual bump. Fonts are self-hosted (`styles/fonts.css`, `fonts/`, OFL texts in `fonts/`; no request to Google Fonts) and the two latin faces are preloaded. Static author and timeline pages also preload `data/authors-detail.js` (`build_static.py`).
- **Layout stability (Phase B item 6).** The header must not reflow when the web font arrives: `.brand-name` has a fixed width in `em` and the search input a fixed line height, so the header is 170 px at 1280, 121 px at 412, and 165 px at 390 with or without the fonts. The inline theme script in `index.html` adds `html.js`; with it, the static prerender in `#main` reserves `min-height:100vh` so the footer never shows in the first screen and then jumps when the app's page replaces it (`html.app-unavailable`, set by `scripts/boot.js`, drops the reservation). Check with a throttled CLS run at 412 px before changing the header, fonts, or prerender.

## SEO and discoverability (v17)

Quality pass (2026-10-26): the shared wording is “a library of libraries,” a selected Catholic reading room and curated resource index. `tools/build_info.py` stamps the original catalog date and deterministic `bc-` application/catalog fingerprint into the home template and every generated page; `build.json` exposes the source hashes. This is not a commit SHA or a fresh review date. Build the home template before static entry pages so copy tokens and fingerprints agree in one pass. `scripts/boot.js` runs in the head and keeps plain content plus recovery links when core startup fails; call `BCBoot.ready()` only after successful app startup. The header is a GET form to `/search/?lookup=...`, intercepted by the app. The `/search/` static directory supports browsing and browser Find without JavaScript; do not promise server-side search. Search suggestions expose combobox state, and failed optional catalogs show incomplete results without automatic retry loops. See `docs/QUALITY-AUDIT-2026-10-26.md`, `CONTRIBUTING.md`, and `SECURITY.md`.

Full notes: `docs/SEO.md`. `tests/test_seo.py` enforces these rules.

- **The home page is static.** `index.html` holds generated regions: `<!-- static-home:start -->…<!-- static-home:end -->` inside `<main>` (the about text and section links from `tools/site_copy.py`) and `<!-- jsonld:start -->…<!-- jsonld:end -->` before `</head>`, plus the `<title>` and meta description (`HOME_TITLE` and `HOME_DESC` in `tools/build_static.py`). Edit `tools/site_copy.py` or `build_static.py`, never the regions by hand. It also writes `data/site-copy.js` (`window.SITE_COPY`, used by `app.js` for the home text and `#/about`) with a content-hash `?v=`. Do not bring back a "Loading…" or noscript-only main.
- **Every indexable page** needs a unique `<title>` that contains "Bibliotheca Catholica", a unique meta description of 120 to 160 characters (aim for 150 to 160 with `fit()`), exactly one `<h1>`, a canonical, `og:*` and `twitter:*` tags, `robots` `index,follow` (flagged books stay `noindex`), and JSON-LD that parses. Index and section pages get a visible intro (`INTRO` in `build_static.py`).
- **Header and footer links are real paths** (`/authors/`, `/about/`, and so on) so crawlers can follow them. `app.js` turns them into hash routes only on the root page; on static pages they load the static page. Keep new nav links as paths.
- **Static cross-links (Phase A, 2026-11-03).** `build_static.py` links the pre-rendered pages to one another by real paths, all from existing data, with no new pages and no keyword lists. A work page has a "Related" list: its edition guides (`workIds` in `data/guide.js`), the reading lists that include it (directly or through their edition guide), saints whose `reading_room_works` or hagiography-shelf entries name it, other works by the same author (up to 8), the hagiography shelf, and, only when that leaves fewer than two links, up to six works of the same category. An edition guide links its author, its reading-room works, and its reading lists. ## Reader storage and features (v11)

Everything a reader saves stays in that browser's `localStorage`; nothing is sent to this site, Google, or anyone else. Keep it that way (no sync, no accounts, no analytics events containing notes or quotes), and keep the Privacy section sentence in `tools/build_editorial_flags.py` accurate.

| Key | Value | Written by |
|---|---|---|
| `bc-notes:<workId>/<editionId>` | `{v:1,items:[{id,s,a:{start,end,exact,prefix,suffix,p,po},c,n,ct,ut}]}`: highlights and notes. `a` is a text-quote anchor: `exact` plus 40 characters of `prefix`/`suffix`, offsets within the section text (paragraphs joined by a blank line), `p` = global paragraph index of the start, and `po` = offset in that paragraph. `c` is `yellow`, `green`, `blue`, or `pink`; `n` is the note. | `scripts/reader.js` |
| `bc-recent` | Continue reading list, newest first, at most 8: `[{w,e,p,n,t,title,author}]` (`p` section index, `n` section count). | `scripts/reader.js` |
| `bc-reading:<editionId>` | Saved section index. | `scripts/library.js` |
| `bc:reader-size`, `bc:reader-spacing` | Display preferences. | `scripts/library.js` |
| `bc-listen:<workId>` | Listen dock state (recording, chapter, time, open). | `scripts/library.js` |
| `bc-plan:<planId>` | `{v:1,read:[day numbers]}`: the days of a dated reading plan (for example `bc-plan:advent-2026`) marked as read. Removed when every mark is cleared. | `scripts/plans.js` |
| `hub-theme` | `light` or `dark`. | `app.js` |

- **Anchoring:** highlights resolve by offset first, then by searching the section for the exact quote and choosing the occurrence whose prefix and suffix match best. Sections are 35 paragraphs (`size` in `read()`); `p` lets highlights find their section even if that size changes. If a passage can no longer be found, My notes still lists it as unplaced. Do not change `splitText()` or the `reading-p-<index>` paragraph ids without a migration.
- **My notes panel:** lists a work's highlights, jumps to them, and edits or deletes them. It exports notes as Markdown or plain text, and backs up or restores everything (notes, Continue reading, saved places, and preferences) as JSON (`format: "bibliotheca-catholica-reader-backup"`, merged by highlight id, newer edit wins).
- **Shortcuts:** ← or k (previous section), → or j (next), / (find in work, overrides the site search only in the reader), t (contents), n (notes), Esc (close a panel), ? (help). `BCReader.core.shortcutAction()` ignores keys while typing in inputs, textareas, selects, contenteditable, or media controls, and with Ctrl, Cmd, or Alt.
- **Edition banner:** "Reading: <title>, tr. <translator>, Project Gutenberg #N" (from `editionLine()`), with "Section X of Y" and a percentage bar. On screens ≤760px it collapses to a one-line chip pinned at the top, the site header scrolls away, and a bottom bar (Prev, Contents, Notes, Find, Next; 44px targets; safe-area insets) hides on scroll down. The Listen dock sits above that bar and moves with it.
- **Print:** `styles/reader.css` has the print stylesheet. "Print / save as PDF" prints the current section or the whole work, and the printout must keep the edition line and the Project Gutenberg license notice (the whole-work printout repeats the notice at the start and end). Never hide `.pg-notice` or `.print-edition` in print.
- **Accessibility:** reader controls have labels, panels move focus in and restore it on close, `:focus-visible` rings are on, and reader text meets 4.5:1 contrast in light and dark (site-wide since v12; see "Palette and text contrast").


## Palette and text contrast (v12)

Colors come from the tokens at the top of `styles.css` (`:root` for light, `[data-theme=dark]` for dark). Any text color, in **both** modes, must keep a contrast ratio of at least **4.5:1** against the background it sits on (3:1 only for large text, 24px+ or 18.66px+ bold). Check both themes before changing a token or adding a text color.

| Token | Light | Dark | Use |
|---|---|---|---|
| `--muted` | `#6f604b` (was `#867660`) | `#a49b8c` (was `#9a907f`) | secondary and fine-print text |
| `--gold-ink` (new) | `#80601a` | `#d9b45a` | gold **text** (eyebrows, dates, counts, brand subtitle, DJVU badge). `--gold` (`#b8892d`) is for borders, rules, and fills only, never small text in light mode |
| `--on-rubric` (new) | `#fff8ea` | `#14161c` | text on `--rubric`/`--rubric2` fills (`.btn`, `.chip.on`, `.mainnav a.on`, Bookshop button, reader controls). Never hard-code `#fff`/`#fff8ea` on a rubric fill: dark-mode rubric is light pink |

## Dated reading plans (v20)

`#/reading/<planId>` and the static `reading/<planId>/` page show a dated plan: one short reading per day, each a deep link into the on-site reader (`#/read/<work>/<edition>/<section>/<paragraph>`). The first plan is **Advent with the Fathers 2026** (`advent-2026`, 26 days, November 29 to December 24). Sources: `tools/reading_plans.py` (each day's passage anchors) and the plan's text file; `tools/build_reading_plans.py` (part of `npm run build`) validates both and writes `data/reading-plans.json` and `data/reading-plans.js`, which CI diff-checks. See `docs/READING-GUIDES.md`.

- **Canonical Advent data source (2026-11-09, owner-approved: "make the advent page match (consistence in data flow is important)").** `data/advent-2026.json` is the one source of truth for every word of Advent with the Fathers 2026 that readers see, on the site and in the Substack posts: per day the date, `liturgicalDay`, `title` ("Day N: theme"), `subtitle`, `theme`, `author`, `work`, `location`, `translation`, `attribution`, `excerpt` (verbatim; blank lines are paragraphs, single newlines verse lines, … a cut), `reflection`, and `links`; plus the page `intro` and the Nov 22 Substack `preview`. Public URL: https://bibliothecacatholica.com/data/advent-2026.json (raw: https://raw.githubusercontent.com/BibliothecaCatholica/bibliotheca-catholica/main/data/advent-2026.json). Bibliotheca Substack and Bibliotheca Media read from it; any wording change lands here first, then is copied to Substack, never the other way round. The site follows its own writing rules in this file and lists each place the Substack draft still differs in that day's `siteRuleEdits` (for example Oxford commas); Substack's attribution line carries a leading em-dash that the site does not render. The builder fails if an excerpt is not word for word from the hosted passage (whitespace, Gutenberg underscores, footnote markers, and padded verse line numbers aside), if a link or date disagrees with `tools/reading_plans.py`, or if a site field has an em-dash; `tests/test_reading_plans.py` (`test_page_matches_the_advent_data_file`, `test_excerpts_match_the_source`) checks the page and the data stay in sync. After editing it run `npm run build` and `python3 tools/build_static.py`.

- **Editions:** hosted reading-room editions only, each with a year before 1931 and its evidence in `EDITION_YEARS` (`edition` year from the title page or note, or `translator` death year when the file names no edition year). Never Orthodoxy (`pg-16769`), never a flagged author or book. Rights badges come from `BCRights.edition()` in the app and are pre-rendered as Public domain (US) on the static page; keep them linking to `/rights/`.
- **Anchors:** paragraph indexes are `splitText()` blocks (the `reading-p-<index>` ids); the link targets `at`, and the whole passage `p` must sit in the same 35-paragraph section. The builder fails if a passage crosses a section or the text's SHA-256 changes.
- **Excerpts:** each day shows the excerpt from `data/advent-2026.json` (the same words as the Substack post), not an auto-quote. It must sit inside the anchored passage `p` and match the hosted text word for word; `tests/test_reading_plans.py` re-matches every piece against the raw file. Never paraphrase inside an excerpt, and never fix a quote on one side only.
- **Copy:** themes, attributions, and reflections come from `data/advent-2026.json`, with Oxford commas and no em-dashes. Markers (`liturgicalDay`) name the Advent Sundays, feasts, weekdays, and the O Antiphons (December 17 to 23) and are tested by date.
- **Browser only:** the static page lists every day; `scripts/plans.js` highlights today (local date, `aria-current="date"`) and saves mark-as-read under `bc-plan:<planId>`. No analytics event is fired. Add a new plan's id to `IDS` in `scripts/plans.js` and a 150 to 160 character description to `PLAN_DESC` in `tools/build_static.py`.


## How to add things

- **Connected timeline:** `scripts/timeline.js` joins authors and the existing saints guide, with by/about reading links and rights-gated read-here buttons. Keep historical flags and the undated group. See `docs/TIMELINE.md` and `tests/timeline.test.js`.

- **A reading-room work or edition:** follow `docs/CATALOG.md`. Edit `data/library.json` (with rights evidence in `data/sources/`, plus `data/texts/` and SHA-256 if hosted), then run `npm run build`.
- **An author or resource:** load, edit, and save with `tools/hubio.py` (`load()` and `save()`) so `catholic-hub.json` and the three browser files (`data.js`, `authors-detail.js`, `isidore-authors.js`) stay in step (`python3 tools/hubio.py` rewrites them; `tests/test_catalog.py` checks). Author ids are kebab-case slugs used in URLs.
- **An edition guide or reading list:** edit `tools/editions_data.py` or `tools/reading_lists.py`, then run `npm run build`. Never add a flagged title.
- **A dated reading plan:** add its passage anchors to `tools/reading_plans.py` and its words to a `data/<planId>.json` text file like `data/advent-2026.json` (see "Dated reading plans" above), add its id to `IDS` in `scripts/plans.js` and its description to `PLAN_DESC` in `tools/build_static.py`, then run `npm run build` and `python3 tools/build_static.py`.
- **An editorial flag:** add the Isidore book id to `tools/build_editorial_flags.py` with a category (`antisemitic-content`, `polemical-historical`, `sedevacantist-position`, or `author-context`) and a factual note. Then run `python3 tools/build_editorial_flags.py`, `python3 tools/build_open_data.py`, and `python3 tools/build_static.py`.
- **A saint:** add the saint to `research/saints-pilot.json` (outside this repo) and rerun `python3 tools/import_saints_pilot.py --research <dir>`, or edit `data/saints.json` directly: every claim needs a `source_url`; tier 1 ids must equal a hub author id; tier 3 saints need a `historicity` flag. Then run `python3 tools/build_saints.py` (it validates, rebuilds the alias table, and fails on an ambiguous multi-word alias) and `python3 tools/build_static.py`. Search aliases: exact keys after NFKD, diacritic stripping, lowercasing, and dropping leading honorifics (Saint, St., Blessed, Pope); bare first names such as "John" are collisions shown as "Did you mean". Add a nickname (for example "Little Flower") to `HAND_ALIASES` in `tools/import_saints_pilot.py`.
- **A rights status:** add a hand-checked entry to `MANUAL` in `tools/build_rights.py`, rerun `python3 tools/build_rights.py --research <research dir>` (or without `--research` to keep the current classification), then `python3 tools/build_open_data.py` and `python3 tools/build_static.py`.
- **A Rites & Liturgy fact:** edit the research copy in `data/rites-src/` (or the review tables in `tools/build_rites.py`: `OVERRIDES`, `UNVERIFIED`, `DROP`, `PUBLIC_NOTES`, `RESOURCE_FIX`, and the cross-link lists), then `python3 tools/build_rites.py` and `python3 tools/build_static.py`. Every description must be 150 to 160 characters (`rites_pages.fit()` fails the build otherwise).
- **LibriVox audio:** run `python3 tools/fetch_librivox.py` (network) and review the matches.
- After any of these, run `python3 tools/build_static.py`.
