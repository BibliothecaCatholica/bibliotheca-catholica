# Build on deploy: stop committing generated pages (plan, November 21, 2026)

Status: proposal for the owner. No code has changed. Target switch: about December 26, 2026, after the Advent freeze.

**Why.** `main` tracks 9,124 files. 7,355 are marked `linguist-generated`, including 6,005 generated `index.html` pages. Every source change rewrites the build ID in every page footer, so any two open PRs conflict and have to be rebuilt. Today's examples are #120 and the #127, #129, and #130 stack, plus "Merge main … and rebuild" commits like those before #133. If Cloudflare Pages builds on deploy, PRs carry only sources.

## 1. What Cloudflare must run

**Build command** (new `tools/deploy_build.sh`, the same steps as CI's `validate.yml`):

```sh
npm ci && npm run build && python3 tools/build_static.py && npm run build:study && python3 tools/assemble_dist.py
```

**Output directory:** `dist/`. `assemble_dist.py` copies every git-tracked file plus the built output, and leaves out `node_modules/`, `.validate/`, `.study-index/`, and `.epub-build/`. This keeps today's served tree exactly. Serving the repo root after `npm ci` would also upload `node_modules`, which risks the 20,000-file Pages cap; today's tree is 9,124 files.

**Versions:** Node 22 and Python 3.12, as in CI. Pin them with `NODE_VERSION` and `PYTHON_VERSION` in the Pages settings, or with `.node-version` and `.python-version` files. Confirm both in the first build log.

**Dependencies:**
- Python: standard library only. All 38 modules the build reaches import nothing third-party.
- Node: `package-lock.json` (esbuild 0.28.2, pagefind 1.6.0, mirador, fuse.js, citation-js). `npm ci` downloads Pagefind's Linux binary from npm.

**Network:** none at build time. The one network path, the feed fetch in `build_v3_data.py`, is skipped by `--catalog-only`.

**Local-only inputs checked (none block the build):**
- Covers need Playwright, but `assets/covers/` is committed and the build doesn't regenerate them.
- `.local/saints-calendar.json` is only the raw import; the day pages come from the committed `data/saints-days.json`.
- EPUBCheck (Java) runs only in the `epub-pilot` workflow.

**Build time:** about 2 minutes here (build 49 s, static 10 s, study 50 s), well inside Pages' limits.

**Build ID:** deterministic. `tools/build_info.py` hashes the inputs and uses no git SHA or clock, so a deploy build gives the same `build.json` `id` as a local build of the same commit.

## 4. Proving the deploy output matches today

1. **Baseline:** at the cut-over commit, `git ls-files -z | xargs -0 sha256sum > committed.sha`.
2. **Deploy build:** in a fresh clone of the same commit, delete every generated path (the removal PR's list), run `tools/deploy_build.sh`, then `cd dist && find . -type f | sort | xargs sha256sum > built.sha`.
3. **Compare:** `tools/compare_tree.py committed.sha built.sha` must report zero missing, extra, or changed files. Any difference blocks the switch until it's explained.
4. **Remote check:** the same tool fetches every sitemap URL plus the root files from the preview deploy and compares the body SHA-256s with the baseline. It also confirms the `_headers` CSP header and, on `pages.dev`, `X-Robots-Tag: noindex`.

## 5. The removal PR (after parity is proven)

**Delete from git:**
- every `*/index.html` listed in `docs/static-pages.txt`, plus `drafts/**`;
- `404.html`, `sitemap.xml`, `robots.txt`, `build.json`, and `docs/static-pages.txt`.

**`.gitignore`:** add the same paths as directory patterns, plus `dist/`. Keep the `.gitattributes` generated markers so stray copies are flagged.

**CI (`validate.yml`):** keep build, static, study, and tests. Replace the page-tree `git diff --exit-code` with:
- a check that `git ls-files` lists no generated page, which guards against re-adding them;
- a sitemap count floor.

Keep the drift checks on the still-committed data bundles.

**Tests that ask git which files exist:**
- `tests/analytics.test.js` (`git ls-files "*index.html"`, which asserts more than 4,000 pages) and `tests/test_isidore_raw_links.py` (`git ls-files`) must read the built tree on disk instead. Otherwise the first fails and the second silently checks far fewer pages.
- `tests/test_saints_calendar.py` uses `git ls-files` only to keep raw data untracked, so it stays as is.
- `tests/test_hosted_counts.py` needs no change: it compares doc counts with the catalog and reads `data/structured/` and `downloads/epub/`, which stay committed.

**Docs:**
- AGENTS.md rules 6 and 8, and "Validate and hand off": "regenerate and commit together" becomes "regenerate locally to test; commit sources only". `robots.txt`, `sitemap.xml`, and `404.html` become build outputs.
- OPERATIONS "Validation": drop "commit generated changes".
- PROJECT-RULES line 63 (protected files).
- CENTRAL: the hosting paragraph, the snapshot, and a handoff entry.
- README's hosting sentence.

## 6. Switch, step by step

1. **PR A** (tooling and tests only; merge on green under standing approval): add `deploy_build.sh`, `assemble_dist.py`, and `compare_tree.py`, and move the two git-based tests to the built tree. Pages are still committed, so production is untouched.
2. **Local parity:** run section 4, steps 1 to 3, at PR A's merge commit, with zero differences required.
3. **Preview (owner, dashboard):** create a second Pages project, for example `bc-build-preview`, on the same repo, with the build command and `dist/` output. It only deploys to `*.pages.dev` and is noindexed, so production carries no risk.
4. **QA on the preview:**
   - section 4, step 4, with all bodies equal;
   - CSP header present;
   - `tests/test_analytics.py` logic run on the fetched pages;
   - `/drafts/` noindex;
   - a 404 test;
   - `node tools/check_plan_ui.js https://<preview>.pages.dev` reads 26/26;
   - the preview `/build.json` `id` equals `main`'s.
5. **Production build switch** (owner, about December 26): set the production project's build command and output. The next deploy of `main`, which still includes the committed pages, must produce the same `build.json` `id` as before.
6. **PR B (removal):** merge, then confirm that the live `/build.json` `id` equals a local build of `main`, and rerun the remote check against production.
7. **Afterwards:** delete the preview project and record the change in CENTRAL and HOLDS.

**Rollback:**
- A failed Pages build leaves the last good deployment serving, so the site stays up.
- For a bad live deploy, use "Rollback" in the Pages deployments list (instant), then revert PR B (which restores the committed pages) and clear the build command, which returns to today's setup.
- PR A is harmless to keep.

## Summary

Cloudflare can build the site itself. It needs only Node 22, Python 3.12, and the npm packages already pinned; nothing at build time depends on this machine or the network, and the build ID doesn't depend on git. We prove the output is identical by hashing every file both ways, first locally and then on a throwaway preview site. Only then, after Christmas, Micah turns on the build in Cloudflare and we delete the 6,000 generated pages from git. Analytics, headers, robots, and the sitemap stay exactly as they are. If anything goes wrong, Cloudflare's rollback button and a git revert restore today's setup in minutes.
